# Go2 项目复盘与下一阶段计划（截至255）

日期：2026-11-12。依据用户“分析一下现在实验的问题并且做一个规划”。本次只核对已有代码、合同、结果和研究方法，新增物理、训练、拟合均为0；未替换正式选择、未发布新版本。下述计划更新后续顺序，不改写历史评分。

## 1. 当前判断

项目已有可用的低速仿真运动系统、有限范围抗扰、首版开源与复现材料。当前主线停在快跑能力和快慢衔接，尚未完成猎犬式奔跑。现有证据没有证明Go2达到物理速度极限，也没有证明PPO或某类动作表达无解。

下一步应改变高速分支的动作组织和训练覆盖，同时明确运动中的稳定定义。继续单独改一个增益、频率或奖励权重，预期价值已低。保留212低速系统和249整合原型，将“周期参考＋本体反馈残差”作为一个有界的新架构试点；不把255提出的关节错相回放再拆成多轮孤立诊断。

## 3. 当前五个主要问题

### 3.1 验收把运动周期波动与未完成变速混在一起

244和原高速框架把`.08m/s / .15rad/s连续25个50Hz控制步`用于停稳。248又将它用于运动中的两次变速，合同没有给出步态周期依据。当前1.75Hz约28.6帧一个周期，25帧占87.5%。252已测8–12秒纯高模式仍有周期性越界，不能全归为模式还没交接完。

这不证明原精度目标错误：它确实能衡量严格瞬时跟踪。但是，仅凭这一布尔条件无法区分稳定的周期运动、明显抖动和持续发散，作为所有新步态唯一入口会让工作偏离实际任务。

**处理：** 下一合同分开定义停止稳定、运动跟踪、模式衔接和新步态质量。运动中同时报告完整周期均值误差、原始速度/yaw RMS、峰值、带外占比和周期间变化；衔接报告进入运行带的时间及随后至少两完整周期的保持情况。明确计时按首合格周期起点还是确认终点、相位来源与低频/缺周期时的处理，不能只滤波后评分。

新增yaw波动、峰值与持续负载等数值必须在新试验前按任务路径容差和允许代价冻结，本次不挑选刚好让253过线的阈值。旧25帧仍输出为诊断；停止、原低速正常和已有抗扰合同不改。248–253继续是原资格失败；即使将来采用新版运动标准，也须在冻结后新条件重新验证，不能重评分后宣布旧阶段完成。

**处理：** 下轮为主要收益和允许代价分别立表。完整性、不能丢失约定旧任务、足端/路径/停稳底线保留；功率、动作变化和跟踪精度允许事前声明的取舍。新的运行负载预算分清瞬时限额、持续负载与相对基线代价，不跨速度直接沿用“249加5个百分点”。253不因此追认。

### 3.3 当前参考与动作范围未能支撑所要求的轨迹

255同步/错相方案的计划四足同时支撑从40帧降为0，但两者最大足端误差均46.83mm，远超2mm；只改善计划接触表没有得到可执行的新步态。该检查把关节目标限制在`nominal±0.35rad`再与原生范围取交集。这是旧策略的软件动作范围，叠加固定机身姿态、指定足轨迹和有限数值求解，不是Go2的物理可达极限。

**处理：** 停止直接重试这条手工足端曲线。优先用249真实关节目标构造有来源的周期参考，以本体反馈作闭环修正。重新定时后的参考不自动成为正确教师；软件范围与原生关节范围、PD跟踪和力矩需求分别检查。若确需调整每关节目标包络，先写出范围与依据并单独冻结，不把整个机械范围直接当可用控制范围。四脚承重与yaw峰的相关性仅用于提出假设，不当已证因果。

### 3.4 训练覆盖和实际使用仍有缺口

244/247训练与评估的外层控制不同；253已把真实整合执行接口接入训练，这是可复用的重要修复。但253的221回合都从同seed热身，只学习6–12秒加速/高段，减速与停止只在评估出现。共享父模型的续训种子也不等于独立完整训练链。

**处理：** 新高速包使用同一个训练/评估动作接口，覆盖起步、高段、减速、交还和停止的完整任务历史；固定有限的速度历史和初态分布。低速冻结模块所走的仿真步、实际学习模块生效步分别计数。增加一次针对模式状态reset的检查，避免为绕过状态残留而永久依赖每回合新建全栈。冻结归一化不能直接接受未见过的侧向命令；250近零方差放大导致失败已说明这是必要接口检查。

253在高策略调用处暂停的队列接口不能只把回合从600延长到1100步：低速交还后可能不再调用高策略，尾段奖励与终止也未必进入学习回报。新包应明确完整50Hz任务step、实际学习动作生效mask和尾段回报归属；不把低速固定策略输出冒充新策略动作，也不能丢掉减速后的代价。这是实际训练语义的必要实现，不安排额外全栈重写。

### 3.5 工作包过碎，下一步建议缺少集中收口

246降频、247duty、250/251命令反馈、253稳定奖励、255静态参考都提供了信息，但尚未汇成一个能训练、运行和评估的新高速模块。新方案很容易又变成一轮统计、下一轮参考、再下一轮补保护，编号增长快于功能增长。

目前已按分级规则省去了逐轮ZIP、全网络/梯度复演，不能再泛称全部时间都耗在防御性审计。主要应缩短从证据到完整闭环候选的路径。

**处理：** 一次集中工作包负责合同、实现、必要接口检查、训练、核心评估和决策；不为每个小参数或统计单开一轮。已有结果直接引用。无收益候选不做全量正常回归、归档复制和交付总览。必要的新接口、评分正确性及失败证据仍保留。

## 5. 新高速模块的技术边界

建议形式为`q_target = clip(q_reference(phase, command) + residual(proprioception, phase, command), declared_limits)`。这是动作组织建议，不是已实现代码。参考只提供周期先验，反馈负责真实状态偏差；相位推进与切换规则也属于控制器状态，必须记录。不得按测试步号、真实外力或场景编号查表供给动作。

参考候选首先来自本项目真实运行；同步/错相只在一个预声明方案中处理，不在看到结果后扫一串相位。参考重新拼接或移相后即是新控制器，必须闭环测量，不能把原249通过项直接移植。若改变输入维数、归一化或动作意义，说明初始化迁移方式，不能声称原PPO权重仍代表同一策略。

该方向参考了[PMTG原论文](https://proceedings.mlr.press/v87/iscen18a.html)的“轨迹生成器与反馈策略组合”思想。后续动物动作重定向可参考[Peng等RSS 2020原项目](https://xbpeng.github.io/projects/Robotic_Imitation/index.html)。这些研究说明方法有先例，不证明本项目必然更快、达到特定速度，或可以直接移用其机器人/数据/权重。

## 6. 后置工作与效率规定

- **当前优先：** 新高速闭环模块、与任务匹配的事前验收、真实模式交接。保持原正常动作、足端、路径和停稳保护。
- **后置但不删除：** 40N跨历史恢复、最终方法三条独立全链训练、统一关键消融和研究报告。选定最终方法后先测一次全流程成本，再安排研究重复，避免在每个临时模型上做三种子。
- **不纳入当前必交：** 复杂地形、导航/感知、真机部署、电池续航与热可靠性。这些需要新的需求和验证范围。
- **每包留存：** 事前配置、真实源码差异及依赖清单、父模型和norm、随机流、检查点、实际控制/训练记录、全部失败、简要结果。阶段成功或关键失败渲染视频，其余保留可重放数据；不逐包复制整个历史树。
- **验证分三级：** 首筛只查实际输入→动作→原生目标、协议/指标与关键对照；有净收益再保护；最终候选集中做依赖恢复、统一评估和视觉验收。涉及结论的矛盾仍须查清。
- **报告只讲四件事：** 本包改变、实测收益、代价/失败、下一决定。无需每轮新交付总览。计划文件顶部只指向最新有效安排，旧记录保留其历史身份。

## 7. 工作量预期

253的65536学习交互加66300热身实际训练约396秒；247的131072交互约261秒。两者接口和环境数不同，不能线性承诺新架构耗时。262144新包纯训练暂预留约15–45分钟，首次接口实现、评估和排错会更长，按实际吞吐更新。

- R0准备与实现：约0.5–1个有效工作日；产出固定合同和可训练接口。
- R1训练、核心评估与一次必要修正：约1–2个有效工作日；产出“可晋级候选”或“证据明确的路线失败”，不保证必过。
- R2若条件满足：约0.5–1个有效工作日。

因此，**2–4个有效工作日应足以对这条新路线作一次完整判断**，不是保证在该时间内完成猎犬奔跑。1.5–2.0m/s和新奔跑形态仍是研究目标，完成日期应等R1真实结果后再估，不继续滚动承诺“再一两轮就好”。
